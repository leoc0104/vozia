# Vozia MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> This plan is executed inline by the same autonomous session that wrote it (the user asked for the build to be done end-to-end without check-ins). Every task still ends with green tests and a commit.

**Goal:** Ship the Vozia MVP — a Supabase + Turborepo monorepo with a React/Zustand SPA, a Node dubbing worker with fake and real drivers, and a Postgres schema with RLS, credits, queue trigger and storage policies — fully tested locally without API keys.

**Architecture:** Supabase provides auth, database (RLS), storage, realtime and the pgmq queue; the browser talks to it directly. A Postgres trigger enqueues every new/retried `dubs` row; `apps/worker` reads the queue over a direct Postgres connection, runs a `DubbingPipeline` (`staged` six-contract pipeline or ElevenLabs end-to-end), writes progress to `dubs` (Realtime pushes it to the UI) and uploads outputs to Storage. `packages/shared` owns the enums, stage/progress map, languages, schemas and SRT formatting; `packages/db` owns the `Database` types, client factories and storage path helpers.

**Tech Stack:** pnpm 11 + Turborepo 2, TypeScript ~6.0, Node 22, Vite 8 + React 19 + TanStack Router 1 (code-based) + Zustand 5 + TanStack Query 5 + Tailwind 4, `@supabase/supabase-js` 2, `postgres` 3 (postgres.js), `tus-js-client` 4, `@anthropic-ai/sdk`, zod 4, Vitest 5, Testing Library, oxlint, pino, Docker (`supabase/postgres:17.6.1.173`) for SQL tests.

**Spec:** `docs/superpowers/specs/2026-09-17-vozia-mvp-design.md`

## Global Constraints

- Package names: `@vozia/web`, `@vozia/worker`, `@vozia/shared`, `@vozia/db`. Root package `vozia`, `packageManager: pnpm@11.10.0`, `engines.node >= 22`.
- TypeScript `~6.0`; `tsconfig.base.json` copied from league-platform (`module: NodeNext`, `strict`, `verbatimModuleSyntax`, `isolatedModules`). Web uses Vite's bundler tsconfig shape (`moduleResolution: bundler`, `erasableSyntaxOnly`). Under TS 6 `types` defaults to `[]` — always set `"types": ["node"]` (worker/packages) or `["vite/client", "vitest/globals"]` (web) explicitly.
- Every driver contract has a fake; fakes are the default outside `NODE_ENV=production`; the whole test suite runs with no API keys, no ffmpeg, no Supabase CLI.
- Status vocabulary is exactly: `queued, ingesting, separating, transcribing, translating, synthesizing, muxing, dubbing, completed, failed`. Pipelines: `staged`, `elevenlabs`. Voice modes: `clone`, `stock`. Source types: `upload`, `youtube`.
- Storage buckets: `sources`, `outputs` (private). Object paths always start with the owner's `auth.uid()`.
- Queue name: `dub_jobs`. Message payload: `{"dub_id": "<uuid>"}`.
- RPC name: `retry_dub(p_dub_id uuid)`. DB error code string for exhausted credits: `insufficient_minutes`.
- Default translation model `claude-opus-5` (env `VOZIA_TRANSLATION_MODEL`); the Anthropic call uses `messages.parse` + `zodOutputFormat`, a cached system prompt, and typed SDK errors.
- Commits: one conventional-commit line, no body, no trailers. Commit after every task.
- English everywhere (code, UI, docs).
